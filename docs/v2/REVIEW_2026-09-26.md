## 5. "Where is agentic AI capability?" — nowhere yet

Today's pipeline is fixed: regex anchor detection, one fixed retrieval, one prompt, one draft, deterministic checks. It cannot follow a second hop, re-query, compute a derived figure or use a tool. The plan's LangGraph agent is M3.

Design (from the audit; libraries verified on PyPI today) — **Option A, about 3 days, $2–4 API** [E; the critic thinks 3 days is optimistic, budget 4–5]:
- Opt-in `strategy=agent`; `hybrid` stays the default. LangGraph (MIT) only, no `langchain`, `create_agent` or `langchain-litellm` (the last had three breaking releases in 48 hours). LiteLLM stays as the gateway. No licence key needed (the paid trap is `langgraph-api`, Elastic-2.0).
- Flow: route → prefetch (today's retrieval) → model with read-only tools → verify → release / escalate. Tools wrap existing code: hybrid and vector retrieval, metric lookup (fiscal-year labelled), dropped-risk lookup, export-rule lookup, filing-status/evidence lookup. Web search (Tavily) only in the fuller option.
- Fuller option B (about 11 days, $8–12): structured claims with per-claim verification, numeric grounding, Langfuse (sampled), DeepEval T0/T1/T2, follow-ups, web search.
- Honest caveats: it will not improve the current 20-question score (that benchmark has no multi-hop, follow-up or tool questions, and — as section 2 shows — it is blind to the errors that matter). Latency rises (8–12 s on loop questions) and cost rises 20–80% blended. Tool calling through LiteLLM on Luna and Sonnet 5 has **not** been probed yet.

## 6. "Where is document upload?" — nowhere yet

No upload endpoint, storage, parser, tenant isolation, ingestion job, runtime passage embedding or UI exists. What is reusable: the pure version-decision logic, the frozen content-hash spec, snapshot ids, the lineage machinery (but see below), a CLI freshness check.
Blockers found: the deployed service has only an ONNX *query* embedder (no passage embedding path) and no parser; the 2 GB API and 1 GB database machines cannot host Docling; the citation grammar, answer-cache key, public stats and graph rebuild (`reset_graph` deletes every non-service node; the DB image re-seed overwrites uploads) all assume SEC-only data.

Design — **Option A, honest scope about 7 days (the auditor's "5" needs eight cuts and a clean Day-1 spike), about $1–2 API** [E]:
- Anonymous 24-hour token workspace, at most 3 documents with version chains; PDF/DOCX/MD/HTML/TXT, about 15 MB / 40 pages.
- Parsing in a **separate on-demand app** running `docling-serve` (Docling 2.130.0, MIT; memory is uncertain by about 3x, so it needs a 4 GB+ machine); the API only validates and streams bytes. No RQ/Valkey/R2 for a one-presenter demo.
- App-level isolation on Neo4j Community (`User*` labels, mandatory `workspace_id`, own vector index, leak tests across retriever, cache, evidence and stats); a separate citation grammar; prompt-injection boundary around uploaded text.
- Version diff by normalised-block hashes at section level, only changed sections re-embedded; the "what changed" report must use **text-grounded** matching, **not** the current greedy clustering (section 1).
- Day-1 spike must settle: Docling memory on Fly, autostop behaviour on a long request, the `(workspace_id, is_current)` filtered index on Community 2026.07.1, remote-embedding parity. Excluded: PyMuPDF (AGPL), `unstructured`, pypdf on untrusted input (10 advisories).
- Caveat: a third-party embedding host would see full document text; needs your sign-off.
