## 1. Findings that change a decision (read this first)

1. **The current CSP is not strict about inline code.** `routes.py:69-71` has `'unsafe-inline'` in both `script-src` and `style-src`. Gate 2 keeps it byte-identical, so under the kept header Vite, Radix, Base UI and shadcn style injection **all pass without nonce work**. The strict-CSP analysis below (sections 3.3, 4) only matters if the owner later tightens the header (a separate, approved change).
2. **Two real constraints exist under today's header:** (a) there is no `font-src`, so fonts fall back to `default-src 'self'` and a `data:` font is **blocked**, while Vite inlines assets under 4 KiB as `data:` by default (`img-src` allows `data:`, fonts do not); (b) `base-uri 'none'` forbids any `<base>` element, so a runtime `<base href>` cannot make one build serve at both `/v2/` and `/`.
3. **`StaticFiles(html=True)` has no SPA fallback and the headers are not attached to it.** Starlette serves `index.html` only for directories and `404.html` on a miss; the CSP dict is applied only inside the `index()` route (`routes.py:171-175`). M5_PLAN 4.7 leaned on Next emitting one HTML file per route; with Vite, `/v2/company/NVDA/` is a 404 unless a catch-all route returns `index.html` with status 200 and `SECURITY_HEADERS`.
4. **The answer renderer is not "plain text + chips" today.** The live page renders a restricted markdown subset (`index.html:275-290`: `esc()` first, then `**bold**`, `-`/`*` lists, `#`..`####` as `h3`, paragraphs, citation chips). M5_PLAN 4.7's "plain text nodes plus chips, no markdown engine" would drop headings, lists and bold: a visible parity regression unless `AnswerText` re-implements those constructs.
5. **TypeScript is now 7.0 (native, Go) and has no programmatic API.** `typescript-eslint` 8.72.1 peers `typescript >=4.8.4 <6.1.0`; the Vite team's own starter (`create-vite` 9.3.4) ships `typescript ~7.0.2` + `oxlint` and no ESLint. TS 7 makes `baseUrl` a hard error while shadcn's Vite page still tells you to set `baseUrl: "."`.
6. **Node: the plan's Node 22 is outdated.** Node 26 became LTS on 2026-10-28; Node 24 (what CI already uses, `.github/workflows/tests.yml:37-39,71-73`) is in maintenance until 2028-04-30; Node 22 ends 2027-04-30. Several tools now need Node >= 22.22 (React Router 8, jsdom 31).
7. **React Router 8 is current and Node-heavy; `react-router-dom` is gone** (import from `react-router` and `react-router/dom`). For five routes it is still the proven choice; wouter and TanStack Router are credible but each carries a caveat (section 3.2).
8. **shadcn/ui's default primitive library is now Base UI (since July 2026); Radix stays supported.** Base UI ships a first-class `CSPProvider`; Radix needs per-component `nonce` props plus a `get-nonce` call for modal components.
9. **`@microsoft/fetch-event-source` is unmaintained and auto-retries by default**: on a dropped stream it would silently re-POST a paid ask. Use `eventsource-parser` 4.1.3 (maintained, parser only, no retry logic) with `fetch`, or port the page's existing reader (and keep `tests/ui/stream_cut.test.mjs`).
10. **"Lighthouse CI is stalled" (M5_PLAN.md:39) is now outdated:** `@lhci/cli` 0.16.0 was published 2026-11-02 (bundles Lighthouse 13.6.0, Node >= 22.19).
