## Today's frontend (verified)
ONE static file, `src/semigraph/serve/static/index.html` (~1,040 lines, inline script and CSS), served by FastAPI at `/`. 149 node tests (`tests/ui/*.mjs`, no npm install) plus pytest source pins. It carries security contracts a rewrite must not lose: a strict CSP (`connect-src 'self'`, no inline eval), server text only ever inserted with `textContent`/escaped (no HTML from the server), citation-chip grammar mirrored from the backend and diffed by a test, Turnstile fail-closed flows with a fresh token per ask and per upload, the private workspace id/token kept in `sessionStorage` only, an evidence cache with stale-version rules, "ask as of vN", a what-changed view, the agent step timeline, a freshness line, cached benchmark examples. Known gaps found in the M5 research: the evidence drawer stays in the keyboard tab order when visually closed; the upload drop zone has no keyboard path; one test pins a field the API never returns. The page works and is live.

## What the plan proposes (docs/v2/M5_PLAN.md, written 2026-09-30)
- M5b: a `web/` Next.js 16 static export (TypeScript, Tailwind, shadcn), AI SDK UI-message-stream (`ai@6` + `@ai-sdk/react@3`; `ai@7` is current; the plan adopts the 6/3 pair because AI Elements pins it) with a NEW server-side encoder `POST /api/chat` in FastAPI (the old SSE grammar stays for `/api/ask`), our OWN restricted answer renderer (plain text plus chip buttons; no markdown/HTML engine) to keep today's XSS invariants, pages Home/Ask, Company dossier, Workspace (M4 parity), Freshness, Method & Limits, the old page kept at `/legacy`; served SAME-ORIGIN from the existing API image (a Node build stage in the Dockerfile, `StaticFiles` mounted after all API routes); first at an unlinked `noindex` preview path `/v2/`, promoted to `/` only on the owner's written sign-off; Lighthouse accessibility >= 95; node CI job.
- M5c (each production enable is a separate owner decision): export to PDF/Markdown with footnoted citations; conversation history held in the browser plus a one-turn follow-up (one extra small LLM call that rewrites the follow-up into a standalone question; a separate prompt template so the SEC-path fingerprint holds; prior turns labelled untrusted; never cached); admin-issued API keys stored hashed in Neo4j with a per-key quota; a read-only MCP server (stateless streamable HTTP; 5 tools: list_companies, get_company_dossier, get_risk_changes, get_evidence, search_chunks (k <= 10, behind the embedding limiter and a 10/min/IP window); no LLM path reachable); a supply-chain map ("as disclosed", node degree computed in Cypher, a table toggle, <= 600 edges, no Graph Data Science plugin); an admin console (cost per answer, cached ratio, routing, kill switch, freshness check, eval scores read from `artifacts/`, a Langfuse link). The "N risks dropped" badge listed in the original PLAN is NOT proposed, because the dropped-risk layer was found mostly unreliable on Nvidia in the 2026-09-26 audit.

## Verified facts (2026-10-03; UNVERIFIED where marked)
- Cloudflare Pages is not formally deprecated, but Cloudflare's docs say "Start new projects with Workers" (Workers Static Assets, deployed with `wrangler deploy`). Static asset requests are free and unlimited (up to 20,000 files, 25 MiB each); requests that run the Worker first count against the 100k/day free limit and get 429 above it; free CPU is 10 ms with 50 subrequests. workers.dev, pages.dev and fly.dev are all on the Public Suffix List, so cookies between them are third-party cookies; CORS preflight gets 403 unless configured. Cloudflare's proxy read timeout is 125 s (524); an open issue concerns buffering of compressed SSE, so SSE must stay uncompressed with a 15-30 s heartbeat. Cloudflare Access Free: 50 users, onboarding needs payment details, one-time-PIN must be enabled manually; it can protect a `*.workers.dev` hostname without a custom domain. A custom domain costs about $10-15 per year (from the plan; not re-verified today). Turnstile is already in use.
- The AI SDK major versions turn over about twice a year (the plan's research); the stream protocol is versioned by a response header; no first-party Python encoder was found, so the encoder is ours and is pinned by byte-level fixtures plus the SDK's own reader.
- An answer-streaming backend change is therefore REQUIRED for the AI SDK path (the research corrected an earlier belief that this was frontend-only).
- Static export footguns: no middleware, no Server Actions, no cookies; dynamic routes need `generateStaticParams`; `trailingSlash` and API exclusion must be tested so `/company/NVDA/` resolves under FastAPI `StaticFiles`.

## Options to weigh
- H1 (plan): no Cloudflare in M5; Next.js static export served same-origin from the API image, at `/v2/` first.
- H2: as H1 but put the frontend on a free `*.workers.dev` Worker that also proxies `/api/*` to Fly (new public hostname; 100k/day Worker-request cap if the Worker runs first).
- H3: a domain on a Cloudflare zone for Pages/Workers + Access invite gate (about $10-15/year; ends open public access if Access is turned on).
- F1: Next.js static export + AI SDK (the owner's recorded choice and the plan).
- F2: Vite + React SPA (no Next.js), the same pages, our own thin streaming client for the existing SSE grammar (no AI SDK, no new encoder).
- F3: do not rewrite: extend the existing single-file page with the new views.
