# Council 3 addendum: facts verified AFTER the advisors answered (2026-10-03)

These supersede anything in the brief or the advisors' answers that conflicts with them.

1. CORRECTION to the brief: today's page does NOT run a "strict" script CSP. The live CSP (serve/routes.py) is: `default-src 'self'; script-src 'self' 'unsafe-inline' https://challenges.cloudflare.com; style-src 'self' 'unsafe-inline'; connect-src 'self'; frame-src https://challenges.cloudflare.com; img-src 'self' data:; base-uri 'none'; form-action 'none'`, plus nosniff, frame deny, no referrer, HSTS. So inline scripts and styles ARE allowed today. The real protections of the current page are: `connect-src 'self'` (the page can call only its own origin), no `unsafe-eval`, server text only ever inserted as text (`textContent`/escaped, never HTML), restricted frames/forms/base, and the tests that pin all of that. The brief's phrase "strict CSP" should be read as that set, not as a nonce-or-hash script policy.
2. Next.js official docs (version 16.3.8, fetched 2026-10-03 from https://nextjs.org/docs/app/guides/content-security-policy and https://nextjs.org/docs/app/guides/static-exports): a static export cannot use nonces (static pages are generated at build time, when no request headers exist; nonces need dynamic rendering). The guide's documented policy for apps WITHOUT nonces is `script-src 'self' 'unsafe-inline'` (and `style-src 'self' 'unsafe-inline'`), which matches today's. A strict hash-based alternative exists only through an EXPERIMENTAL Subresource-Integrity feature (App Router; "may change or be removed"). In a static export these Next features are unsupported: `headers()` config, Proxy (middleware), cookies, rewrites, redirects, Server Actions, ISR; dynamic routes need `generateStaticParams()`. Therefore a Next.js static export cannot be worse than today's CSP on scripts, but it also cannot be made stricter without the experimental feature; the CSP header would be set by our FastAPI middleware either way (the plan already does this).
