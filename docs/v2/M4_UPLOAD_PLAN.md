# M4-A: thin document upload - implementation plan (2026-09-26, fable-architect review of branch v2)

Status: design only. Goal: a buyer uploads a document (and later a new version), asks questions that cite it, sees old citations flagged stale, and gets a text-grounded "what changed v N -> N+1" report. The SEC path stays byte-identical.

## 0. Facts verified in the code that shape the design
- The API machine is 2 GB + 1 GB swap; the 1 GB machine is Neo4j. The ONNX q8 embedder already uses ~1 GB; Docling (1.0 GB steady / 2.1 GB peak) cannot run on the API machine. `OnnxBackend.encode_passages` exists (unbatched, throughput unmeasured).
- The serve image has no pandas/pyarrow/lxml/bs4/scipy/rapidfuzz/python-multipart: upload code may import only `graph/alignment.py`, `graph/passages.py`, `graph/align_text.py`, `hashing.py`, `versions.py` constants; never `graph/items.py`, `parsing/chunker.py`, `parsing/risk_items.py`.
- `retrieval/ids.py` is the only citation grammar; `answerer.sources_from_context._EXCERPT_ID_LINE` matches only SEC chunk ids (an upload number would fail `numbers_grounded` and escalate every time).
- `template_fingerprint()` hashes `ANSWER_PROMPT + CONTEXT_HEADERS`: touching either un-seeds every example on boot; no 7th block can be added to the SEC template.
- `graph/schema.reset_graph` keeps only `Svc*`; `main.graph_stats` publishes every non-`Svc` label count. The answer cache key has no workspace: workspace answers must not be cached. pymupdf (AGPL) must never reach the serve image.

## 1. Architecture
Parser: sandboxed subprocess on the API machine with pdfplumber (+ pypdfium2) for PDF, python-docx for DOCX, stdlib `html.parser`, plain text/Markdown. docling-serve stays an optional second Fly app, added only if the Day-1 spike on the owner's sample documents shows a need. OCR: none (a PDF with < ~200 chars/page is rejected as scanned). Limits: 15 MiB, 40 pages, 3 documents x 5 versions, 120 pages per workspace.

Package `src/semigraph/uploads/`: `gate.py` (magic bytes, caps, PDF active-content scan, DOCX zip checks) -> `parse.py` (subprocess, 90 s wall, RLIMIT on Linux; bytes never persisted) -> `units.py` (canonical text = blocks joined like `chunker.SEP`; heading-led units else paragraph units; chunks are exact slices) -> embed (hash-keyed reuse; only changed units embedded) -> `changes.py` -> `repo.py` (one transaction).

Graph: `UserWorkspace -OWNS-> UserDocument -HAS_VERSION-> UserVersion -HAS_UNIT-> UserUnit`, `UserVersion -HAS_CHUNK-> UserChunk` (embedding, is_current, valid_from/valid_to, status, suspicious), `UserVersion -SUPERSEDES {kind:'rolled', items_compared, not_compared_reason}-> older`, `UserUnit -SUCCEEDED_BY->`, `UserUnit -HAS_PASSAGE-> UserPassage`. Every node carries `workspace_id`; every Cypher binds `$ws` (a unit test greps every query). No edge ever touches Company, Filing, EvidenceSpan or RiskItem. Schema: uniqueness constraints, `expires_at` index, a NEW vector index `user_chunk_embedding` filtered on workspace_id/is_current/document_id/version/valid_from/valid_to (not in REBUILD_INDEXES); `PRIVATE_LABEL_PREFIXES = ("Svc", "User")`.

Isolation: 128-bit workspace token, only its sha256 stored, `X-Workspace-Token`, constant-time compare, 404 on any miss; workspace retrieval is a separate in-index SEARCH `WHERE workspace_id = $ws AND is_current = true`; workspace answers skip the answer cache; 24 h TTL + sweeper + DELETE endpoint.

Versions: explicit "new version of <document>" only; identical content hash -> `{unchanged: true}`; version ordinal decides currency (never `compute_filing_versions`); older chunks flip `is_current=false, status='superseded'` in the same transaction; `as_of` filters `valid_from <= d < valid_to`.

## 2. "What changed" = `alignment.align` + `passages.compute_passages` (both pure and pandas-free; no change to them)
`uploads/changes.py` builds rows shaped like `graph/items.item_rows()`, runs lexical-only `align`, then `compute_passages` with each version's chunk spans. Needed generalisations live outside alignment: (a) unit detection for arbitrary documents (headings from font size/bold, DOCX styles, Markdown `#`; paragraph fallback), (b) the whole document is one section, (c) a not-compared gate (`items_compared=false` with a reason when a parse is untrustworthy: text yield, parse-method mismatch, heading coverage), identical hashes render "no changes (identical content)". Every passage cites a chunk id of the version it is quoted from, and a test asserts the quote is contained in that chunk.

## 3. Security
Content-sniffed allowlist, streamed size cap, PDF active-content byte scan (/JavaScript, /JS, /Launch, /OpenAction, /AA, /EmbeddedFile, /RichMedia), DOCX zip limits, parser killed on timeout, originals never stored. Prompt injection: uploaded text goes only into a separate block of a separate template `answer_workspace.txt` inside a per-request random delimiter, model output stripped of Markdown images/links, heuristic `suspicious` flag (banner, never blocks); upload text must never reach tool selection (M3). Retention: text + vectors for <= 24 h, logs carry a workspace-id hash only, no remote embedding backend without owner sign-off. Abuse: Turnstile fail-closed on workspace creation and each upload, per-IP limiter, quotas, daily ceiling, kill switch, an upload semaphore so embedding never starves answers.

## 4. API + UI
`POST /api/workspace`, `GET/DELETE /api/workspace/{ws}`, `POST .../documents` (multipart, optional `document_id` = new version, 202 + job), SSE job events (`received -> validating -> parsing -> chunking -> embedding -> comparing -> indexing -> ready|failed`, job persisted as `UserJob`), `GET .../changes?from=1&to=2`, `POST /api/ask` gains `workspace_id` and `as_of`, `done` gains `stale_citations`. Id grammar: `DOC_ID_PATTERN = doc:<12hex>:v<n>:<seq4>` added to `CITE_RE` / `classify_id` (the workspace id is NOT in the citation); extend `_EXCERPT_ID_LINE`. UI: `workspace.js` + a panel in `index.html`: create/restore workspace, drag-drop upload with progress, document list with version timeline, "What changed v1 -> v2" view, `doc:` chips, stale chips turn red after a new version.

## 5. Day-1 spikes, gates, breakdown, estimate
Spikes (each < $0.05, < 1 h): S1 ONNX passage throughput; S2 create `user_chunk_embedding` with the six filter properties on a scratch DB and run the filtered SEARCH; S3 pdfplumber + pypdfium2 on a 40-page PDF (chars/page, heading detection, RSS) plus active-content false positives; S4 `align` + `compute_passages` on two revisions of a non-SEC text (proves no alignment change is needed); S5 current serve RSS on Fly.

Shared surfaces first (main, 0.5 d): `retrieval/ids.py`, `_EXCERPT_ID_LINE`, both schema.cypher copies, `graph/schema.py`, `config.py`, `deploy/requirements-serve.in` (+ python-multipart, pdfplumber, pypdfium2, python-docx), `serve/main.py`, `store.py`; a test pins the CURRENT `template_fingerprint()`.
Worker A (2 d): `uploads/{gate,parse,units}.py` + fixtures (text PDF, PDF with /JavaScript, encrypted PDF, exe renamed .pdf, DOCX, zip-bomb DOCX, MD v1/v2 with a known edit set). Worker B (2.5 d): `uploads/{versions,repo,changes,jobs}.py` + leak integration test. Worker C (2.5 d): `serve/workspace_routes.py`, `retrieval/workspace.py`, `answer_workspace.txt`, routes seam, `workspace.js`. Then integration + deploy + verifier (1.5 d).
Estimate: ~9.5 engineering days (~7 calendar with three workers), API <= $1.5. If only 60% fits: PDF + MD/TXT only, no DOCX/HTML/as_of/band adjudication, heuristic injection flag, panel instead of a page; never cut the leak harness or the fingerprint pin.

## Where the obvious implementation is wrong
Putting upload chunks in the EXCERPTS block or editing `answer.txt` (un-seeds every example); using `compute_filing_versions` / `graph/temporal.py` for uploads; forgetting `_EXCERPT_ID_LINE`; the research doc's block-hash diff, `cluster_lineages` reuse, LLM "deep mode", RQ/Valkey/R2 and a separate parse app are obsolete after M1b; a citation form that embeds the workspace id leaks it in exported answers.

## Acceptance checks for the verifier
SEC path untouched (tests green, pinned fingerprint, examples still seeded, no diff under alignment/passages/freshness/versions); leak harness (two workspaces + public data: zero foreign rows on ask, evidence, workspace routes, stats; public ask never issues the workspace SEARCH; `graph_stats` shows no `User*`); versions (v1 answers cite v1; identical re-upload no-op; v2 flips v1 stale; evidence says superseded; `as_of` works); what-changed reports exactly the known edit set with tense-only edits absent and every quote contained in its chunk; each security fixture rejected with zero writes, parse killed at timeout, injection flagged with no link/image in the answer; quotas/TTL; image builds, pip-audit clean, no AGPL package in the serve requirements, RSS after a 40-page upload < 1.6 GB, spend <= $1.5.
