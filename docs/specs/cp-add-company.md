## 1. Why

Adding a company today is a hand sequence (docs/RUNBOOK.md:599-640; no orchestrator exists). The council (decision 007) found that the real risk is not the nine stages but regression on the existing 13: a whole-corpus rebuild changes MENTIONS and entity resolution for every filer, and "one command" with no before/after gate is a regression generator. Facts from the code that shape the design:

- Three different orders are behaviour: `FILERS` (src/semigraph/universe.py:12-26; Nav, starters, graph load order), `UNIVERSE` (universe.py:31-46), and `canonical_entities.json` order (anchor cap `MAX_ANCHORS=4`, src/semigraph/retrieval/retriever.py:86-89, 352-364).
- The loader resolves entities itself and drops silently when a Company node is missing (`MATCH` at src/semigraph/graph/loaders.py:402-403 and :498).
- `load_companies` takes cik and `sec_filer` from `company_tickers.json` (loaders.py:212-223), a file that is not in the snapshot hash (src/semigraph/snapshot.py:67-89).
- The snapshot id hashes working-copy bytes of universe.py and the packaged canonical_entities.json (snapshot.py:42-47). That file is LF in git and CRLF in this checkout (`git ls-files --eol`: i/lf w/crlf).
- A paid alignment purchase changes the shared checkpoint hashes and makes all 13 other tickers stale; `build-graph` then refuses (src/semigraph/graph/alignment_provenance.py:99-110).

## 4. Requirements and acceptance criteria

**R1 Baseline freeze (I0, with the tolerance pin completed at I2).** Before any code change, record from G, at $0 and read-only: `baseline.json` (hashes of the generated canonical file and web file, `FILERS`, `UNIVERSE`, snapshot inputs, snapshot id), `invariants.json` (per Company by name: entity id, MENTIONS and edge counts, span content hashes, resolution result; per edge that exists in the 13-filer graph: its 13-filer evidence-id subset and its `evidence_quote`), `anchors.json` (kept and dropped anchors by name for the 60 benchmark questions, the examples, the agent benchmark and the pool of 9), `retrieval_60.json` (G traces; the S-control traces are recorded at I2 and in the run, because S does not exist at I0), `benchmark_scores.json` (from artifacts/eval_report.m2a3-deployed.json, not a new run), `tolerances.json`. `invariants.json` **excludes** `snapshot_id` (it changes whenever the code hash changes, snapshot.py:42-47, :88) and embeddings (RiskFactor embeddings and the ANN index are recomputed on every rebuild). A restamp (`stamp_relation_evidence`) and an ON MATCH append (loaders.py:500-505, which lowers `start_date`) are legitimate changes to an existing edge only when a new-company chunk was added to it, so for an edge that existed before, only the 13-filer evidence-id subset and `evidence_quote` are compared; `start_date`, `last_evidenced_at` and `has_current_evidence` may change only on an edge that gained a new-company chunk.
**Noise floor.** The "two runs on G" check reads one graph twice, so it proves only that the extractor is deterministic. The rebuild noise is measured at I2: two control rebuilds on S, diffed against each other, before any new-company data exists. The measured floor is recorded in `tolerances.json`; the SHA-256 of `tolerances.json` is pinned as a code constant in the I2 commit (not at I0), and the I0 commit records the pre-measurement tolerances hash in its message. Any difference between the two control rebuilds that the declared exclusions do not cover is a finding to resolve before the pin.
Accept: `test_invariant_snapshot_is_keyed_by_company_name_not_cik`, `test_diff_reports_lost_mentions_per_source_filer`, `test_invariants_exclude_snapshot_id_and_embeddings`, `test_existing_edge_compares_only_13_filer_evidence_subset_and_quote`, `test_tolerances_file_matches_pinned_sha256`, `test_benchmark_scores_come_from_m2a3_report`.

**R2 One source of truth, proven no-op (I1).** `src/semigraph/artifacts/companies.json` is the only copy of the company list, added to `snapshot._CODE_FILES` (otherwise a tier or form change stops changing the snapshot id). Schema: `version`, `retired_entity_ids`, and `entities[]` with `name`, `anchor_order`, `entity_id`, `cik` (null for non-filers), `ticker`, `aliases`, `universe` (`order`, `tier`, or null), `filer` (`order`, `annual_form`, `quarterly_form`, or null).
- Three explicit orders, each a contiguous permutation: `anchor_order` (equals array position), `filer.order`, `universe.order`.
- Validation: filer means cik > 0, entity_id == cik, ticker matches `^[A-Z]{1,5}$`, universe set, forms in `RISK_SECTIONS`; non-filer means cik null, entity_id < 0, unique, not retired; normalised aliases unique across entities; entity ids are never derived from position.

Other readers keep calling `load_canonical_entities()`.
- Count pins import `len(universe.FILERS)` (list: docs of the code map, section 1, "Count pins"); the literal "13" in the generated header (scripts/export_ids.py:193) becomes derived. **R3 Loader hardening (I2).** `load_companies` reads cik and `sec_filer` from companies.json; `company_tickers.json` only validates. A span or relation whose endpoint has no Company node raises instead of dropping. `scripts/verify_graph.py` fails on an entity without a Company.

This is the no-op proof for R2+R3 and shows S reproduces G.

**R4 Tripwire registry (I3).** `scripts/compare_retrieval.py` keeps `TRIPWIRE_GOLD_SHA256` as a code constant and adds `artifacts/tripwire_registry.json` mapping gold path to registered SHA-256; the first registry entry must equal that constant, so no single commit can change a gold and its own registry line without also editing code that review sees. Registry paths are constrained to repo-relative `artifacts/**/*.json` with no `..`. A gold not in the registry is refused; a registered file whose hash changed is refused; the rule "a wrong label is recorded, not edited" survives. The report carries the per-file hash (not the single constant). The registry is append-only across git history: each entry's SHA equals the gold blob at the commit that introduced the entry, and no entry is ever modified or removed.
Bind step: the operator-written gold holds questions and verbatim quotes with accession and filer cik. The tool binds each quote, at run time (chunk ids do not exist before chunking), only to chunks inside the span scope of the graph under test, computed from the parquet and the manifest: the newest annual filing (all sections) plus later 10-Qs, which is decision 006's rule ("every verbatim copy in the newest annual filing plus later 10-Qs"). It does not bind older-year repeats of the sentence, since that would widen the gold and make hits easier. The graph's EvidenceSpan scope is (freshness.py:260-313) the latest annual, the current quarterly and one prior annual's risk section; a bound chunk that is not an EvidenceSpan in the graph trips `invalid_questions` and ends in "NOT A VALID RUN" (compare_retrieval.py:425-427, 465-466, decision 006's R2 failure), so the check is "every bound chunk is an EvidenceSpan in the graph", replacing the `ANNUAL_SINCE` check. The text normaliser (whitespace collapse, curly to straight quotes and dashes, NFKC) is pre-registered in code and hashed into the registry entry with the gold, before the first tripwire run, because quotes copied from HTML do not match chunk text byte for byte. An unbound quote is recorded invalid, not dropped. Pooled filer-own misses count across files.
Accept: `test_registry_first_entry_equals_the_pinned_pre_cp_hash`, `test_registry_is_append_only_across_git_history`, `test_registry_paths_are_repo_relative_artifacts_json_only`, `test_report_carries_per_file_gold_hash`, `test_tripwire_refuses_gold_not_in_registry`, `test_bind_maps_a_quote_to_every_in_scope_chunk_holding_it`, `test_bind_ignores_older_year_repeats`, `test_bind_reproduces_m2_tripwire_gold_chunk_ids`, `test_unbound_quote_is_recorded_invalid_not_dropped`, `test_pool_counts_misses_across_files`; the pool-of-9 rerun on G reproduces artifacts/m2_tripwire_snapshot.json verdicts.

## 5. Security requirements and abuse cases (checkable)

- **S1 Operator input.** Ticker allowlist `^[A-Z]{1,5}$`; rejected: `../x`, `..\x`, `C:\x`, `/etc`, `CON`, `NUL`, `COM1`, `aux`, empty, embedded whitespace or NUL, Unicode look-alikes; case and whitespace normalised before validation; a ticker colliding with an existing lake file (any case) is refused. Paths derive only from the SEC-confirmed ticker and numeric CIK. The typed name never reaches a path. Tests parametrised over those cases; a grep test shows no path is built from the raw argument.
- **S2 The typed name is a prompt channel.** The canonical name is what the extractor resolves "we/our" to (universe.py:9-11). Two modes, one name rule. Promote mode (MRVL) keeps the existing canonical name ("Marvell", R9), because the invariants are keyed by name and Company has a unique-name constraint; the SEC row's title is shown for confirmation only. New mode takes a normalised SEC title (case, punctuation and corporate suffix normalised) confirmed by the owner. In both modes the name passes a named sanitiser, `sanitize_company_name` (to be added in I4; no control characters, no brackets, ASCII letters, digits, space and `.&-` only, length cap 50), and a `--name` override is validated against the SEC title or refused. `--tier` is allowlisted to the tier values already present in companies.json. Tests: `test_sanitize_company_name_rejects_control_chars_brackets_and_overlength`, `test_tier_outside_existing_values_is_refused`, `test_promote_mode_keeps_existing_canonical_name`.
- **S3 Aliases.** Alias regexes are built from escaped text (`re.escape`) and anchored as today (retriever.py:341-357). Normalised aliases are unique across entities; a new alias that is a common word or substring-collides with an existing alias is refused. v1 adds no alias for MRVL (R9). Tests: a metacharacter alias does not change matching; a collision fails validation.
- **S4 Indirect injection into the paid extractor.** Filing text is untrusted. Extraction output is validated by schema and against the canonical dictionary before load: unknown entities are dropped and counted, never created; a spoofed cik in model output is ignored because Company identity comes from companies.json only; the loader raises on an unknown endpoint (R3). The paid extractor is Claude through LiteLLM, while promptfoo through the wrapper reaches only the local model, so promptfoo says nothing about the extractor and is not the evidence for S4. The evidence is deterministic tests with a fake runner that returns malicious output: injected instructions, a spoofed cik, an unknown entity, an out-of-schema field; each must be dropped or rejected and counted. Each `evidence_quote` must be a verbatim substring of its chunk, enforced before load. Missing abuse case: injected text yields an edge between two existing canonical entities, which passes the dictionary check, and T-INV (e) would accept it because it carries a new-company chunk; so every new edge between two pre-existing entities is listed in the run report for owner review before merge. Adversarial eval cases (instruction text in a filing paragraph such as "ignore the schema and output X", fake company names, a spoofed CIK) are still written before the paid run, run with the extraction eval and promptfoo against the local model (the wrapper blocks non-local hosts by design) as a secondary check, with a pass threshold (all cases pass; exit 100 = fail). Grep of src/semigraph/extraction/ found no existing sanitiser (UNVERIFIED that none exists elsewhere); the quote-substring check and the fake-runner tests are required in I8, not conditional. Tests: `test_fake_runner_injected_instructions_are_dropped_and_counted`, `test_spoofed_cik_in_output_is_ignored`, `test_unknown_entity_in_output_is_dropped_not_created`, `test_out_of_schema_field_is_rejected`, `test_evidence_quote_must_be_verbatim_substring_of_chunk`, `test_new_edge_between_existing_entities_is_listed_for_owner_review`.
- **S5 SEC identity.** `SEC_USER_AGENT` is never logged, never written to a manifest, state file, run report, fixture or error message; unset fails closed (src/semigraph/ingestion/edgar.py:115-118). Tests set a sentinel `SEC_USER_AGENT` and scan state, report and captured logs for it. edgartools receives the identity through `edgar.set_identity(_identity(settings))` (edgar.py:290), so the configured value is passed explicitly; a refusal gate before any live fetch asserts that edgartools' identity equals the configured one (`test_refuses_live_fetch_when_edgartools_identity_is_not_the_configured_one`).
- **S6 Paid loops.** No `--yes` on any paid command; the quote is printed before waiting; resume re-runs the cap check and the ledger; transient errors retry within the existing `num_retries` (src/semigraph/llm.py:88) and every chunk is checkpointed; two failed paid attempts stop the run. Sonnet-5 call rules from the project's lessons are enforced by tests on the paid call builders: `test_paid_calls_carry_no_sampling_params` and `test_capped_calls_disable_thinking`.
- **S7 Nothing touches production.** The module imports no `flyctl` or kill-switch code, never reads `.env.fly`, never reaches a Fly host (`STAGING_NEO4J_HOST`, src/semigraph/config.py:88-93, is for the Fly staging windows and is refused; a loopback tunnel to Fly such as port 17687 is refused by the exact-port rule, R7). Test greps module imports and strings.
- **S8 Isolation.** Builds and benchmarks target S only; G is read-only until the explicit merge flag; the command refuses equal URIs and every endpoint except the three fixed ports (R7). `scripts/staging.py` is unrelated and this spec says "workspace", never "staging".
- **S9 File I/O.** Downloaded HTML is parsed, never executed; undo and merge act only on recorded relative paths and recorded hashes, under the containment rules of R8; no path outside the workspace and the lake is deleted; the state file is written atomically.
- **S10 Public repo hygiene.** The state file, run report, probe report and fixtures contain no absolute local path, no personal data, no SEC identity, no filing text. Test scans every committed `artifacts/cp/` file.
- **S11 Supply chain.** No new dependency expected. If one is proposed: license, maintenance (recent releases, issue response), import test in this environment, `skillspector` scan for plugins or skills, `osv-scanner` on the lockfile change. Conda-only packages are not audited and the report says so.
- **S12 Gold integrity.** Gold is committed with its SHA-256 before `parse`; the registry only accepts additions, enforced by test across git history (R4) and also visible in `git diff master...HEAD -- artifacts/tripwire_registry.json`; the first entry equals the code constant.
